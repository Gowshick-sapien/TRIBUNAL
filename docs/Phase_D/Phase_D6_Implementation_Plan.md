# Phase D.6 — Interactive Investigation Report & Export Platform (Implementation Plan)

## Objective

Transform the static Markdown investigation report generated in Phase C into a rich, interactive report platform that enables investigators, auditors, reviewers, and compliance officers to explore, navigate, annotate, export, and share investigation reports through a modern browser interface.

Phase D.6 provides an explainable, presentation-ready report workstation that operates exclusively on persisted reports generated by Phase C and stored by the Phase D.2 Repository Layer without executing new investigations.

---

## Architectural Position

```text
                     Investigator
                           │
                           ▼
            Interactive Report Viewer (D.6)
                           │
             REST API (/api/v1/report/{id})
                           │
                           ▼
                 Repository Layer (D.2)
                           │
                Persisted Investigation Report
                           │
──────────────────────────────────────────────
         Phase C Report Generator
──────────────────────────────────────────────
Summary │ Evidence │ Defense │ Tribunal │ Audit
```

---

## Design Principles

1. **Report-Only Layer**: The viewer never regenerates reports; it strictly loads persisted reports from the D.2 repository.
2. **Human-First Design**: Structured section navigation allows reviewers to jump directly to critical sections without manual scrolling.
3. **Explainability**: Every conclusion links back to Investigation Cards, Evidence Graph nodes, and Tribunal reasoning.
4. **Cross Navigation**: Evidence Cards integrate directly with the D.4 Evidence Graph Studio.
5. **Immutable Reports & Separated Annotations**: Original report content remains immutable. Investigator notes and annotations are stored independently in SQLite.

## Components & Modules Built

### 1. Storage Layer & Database Annotations (`storage/`)
- [database.py](file:///d:/TRIBUNAL/storage/database.py): Extended SQLite schema adding `report_annotations` table with foreign key cascades and indexes.
- [report_repository.py](file:///d:/TRIBUNAL/storage/repositories/report_repository.py): Extended `ReportRepository` abstract interface, `ReportAnnotationRepository` note CRUD helper, and `render_compliance_html()` multi-format serializer with print-ready CSS stylesheets.

### 2. REST Reports API Router (`api/routes/`)
- [reports.py](file:///d:/TRIBUNAL/api/routes/reports.py): Versioned endpoints under `/api/v1`:
  - `GET /api/v1/report/{id}` & `GET /api/v1/reports/{id}`: Supports `format=markdown|html|pdf|json` and Accept header content negotiation.
  - `GET /api/v1/reports/{id}/annotations`: Returns investigator notes attached to a report.
  - `POST /api/v1/reports/{id}/annotations`: Attaches a new investigator note annotation (`author`, `text`).
  - `DELETE /api/v1/reports/{id}/annotations/{note_id}`: Removes an annotation by ID.

### 3. Frontend Types & API Client (`dashboard/src/`)
- [types/report.ts](file:///d:/TRIBUNAL/dashboard/src/types/report.ts): Data contracts for `StructuredReportPayload`, `ReportSectionItem`, `ReportAnnotation`, `EvidenceCardItem`, `DefenseItem`, and `ExportFormat`.
- [services/report_api.ts](file:///d:/TRIBUNAL/dashboard/src/services/report_api.ts): Axios API client wrapper for `/api/v1/reports/*`.
